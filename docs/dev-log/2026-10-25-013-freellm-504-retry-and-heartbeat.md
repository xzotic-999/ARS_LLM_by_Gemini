# DEV-013: Защита от `HTTP 504 Gateway Timeout` при ротации моделей FreeLLMAPI (`auto`) и SSE Heartbeat

**Дата:** 2026-10-25  
**Статус:** Выполнено

## Причина бага (`FreeLLMAPI stream returned HTTP 504` на 3-м сообщении)
1. **Таймаут отдельных провайдеров внутри пула `FREELLM_MODEL=auto`:**
   - При последовательных запросах (`привет` -> `как ты?` -> `у тебя есть память?`) роутер `auto` в FreeLLMAPI распределяет запросы между 288 бесплатными моделями/провайдерами.
   - Когда `auto` попадает на «зависший» провайдер или тяжелую reasoning-модель, которая долго не отдает заголовки/токены `delta.content`, прокси **VS Code Dev Tunnel (`euw.devtunnels.ms`)** обрывает соединение по истечении 60 секунд с ошибкой **`HTTP 504 Gateway Timeout`**.
   - Кроме того, некоторые reasoning-модели (`dots-studio/dots-3-note-preview:free` и др.) возвращают токены в поле `delta.reasoning` / `delta.reasoning_content`, оставляя `delta.content: ""`.

## Выполненные изменения
1. **`/server.ts` — Многоуровневый автоматический повтор (Auto-Retry) и быстрый таймаут попытки:**
   - Вместо ожидания 60–120 секунд до падения туннеля по `HTTP 504` задан таймаут первой реакции провайдера `24_000 ms` (`PER_ATTEMPT_INITIAL_TIMEOUT_MS`) и контроль простоя чтения чанков `25_000 ms` (`PER_CHUNK_IDLE_TIMEOUT_MS`).
   - Если первая потоковая попытка (`stream: true`) возвращает `HTTP 408 / 429 / 500 / 502 / 503 / 504`, зависает дольше 24 секунд или закрывается без токенов, `server.ts` **не закрывает соединение с ошибкой**, а автоматически делает повторный запрос к FreeLLMAPI (`auto`), чтобы роутер выбрал следующего рабочего провайдера, а на финальной попытке переключается на `stream: false` (задействуя внутренний механизм failover самого FreeLLMAPI).
   - Добавлена поддержка резервного чтения `delta.reasoning` / `delta.reasoning_content`, если модель вернула ответ только в поле рассуждений.
2. **`/server.ts` — Каждые 5 секунд SSE Heartbeat (`: keep-alive\n\n`):**
   - Во время ожидания ответа и автоматического переключения провайдеров сервер отправляет комментарий `: keep-alive\n\n` каждые 5 секунд, чтобы Cloud Run, Google Frontend и браузер не разрывали SSE-соединение по таймауту неактивности.
3. **`/src/services/api.ts` — Прозрачный клиентский повтор (`chatApi.streamCompletions`):**
   - Если первый запрос завершился сбоем шлюза до получения первого токена (`!receivedAnyToken`), клиент автоматически повторяет запрос в режиме `stream: false` перед показом плашки ошибки.
